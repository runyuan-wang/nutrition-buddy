## 一、结论与定位

营养Buddy 目前挂着「buddy」的名字，却没有继承任何 buddy 家族的**智能体底座**。家族其余成员（QClaw / OpenClaw / Codex / 灵台 / mcporter / skillhub，以及 WorkBuddy）都是「智能体操作系统」——具备 Skill 技能系统、MCP 连接器、记忆系统、多模型路由、多智能体、画布、浏览器、定时任务等底座能力。

而营养Buddy 现状是：

- 单一 Electron + React 应用，v0.1.0
- 对话只接一个模型（K3），7 个硬编码工具
- 没有 Skill 系统、没有记忆、没有 MCP、没有画布、没有多智能体
- 人格只是 `persona/` 下的静态 md，并非运行的「人格引擎」

**关键反差**：营养Buddy 手里其实攥着整个家族**最深的领域知识**——14 个营养 SKILL、你蒸馏的 10 部食养指南、386 食物 / 255 GI 的本地库、血脂 / 控糖 / 儿童肥胖三套临床工作台。它差的不是内容，是**外壳基因**。

**一句话定位**：把家族底座接进营养Buddy，让它成为「最有价值的领域专家 Agent」，而非一个孤立小工具。

**对标锚点（LearnBuddy）**：腾讯云 Buddy 家族首个行业智能体 LearnBuddy（教育垂直，WorkBuddy 同源底座）有四大能力：多智能体协作 / **专家分身（核心）** / 跨会话长期记忆 / Skills 生态。营养Buddy 与它同范式（垂直行业智能体），四项对照：多智能体、跨会话记忆 = 缺失；Skills、专家分身 = 部分（已有 14 SKILL + 10 指南的"私域知识"，但无"分身机制"与"本人校准闭环"）。**最大代差 = 专家分身机制**，而原型本人（王润圆·注册营养师）正是待复刻的专家——这是 Phase 0.5 已落地的内容。

## 三、目标架构：营养Buddy v2 = 领域专家 Agent

复用家族的「五层」心智模型，保留营养Buddy 已有的领域资产，补齐缺失的底座层。

```
┌──────────────────────────────────────────────────────────┐
│                    交互层 (Desktop UI)                      │
│  Electron+React · 对话 · 画布/Artifact · 多窗口 · 报告导出  │
├──────────────────────────────────────────────────────────┤
│                    人格层 (Persona Engine)                  │
│  SOUL/IDENTITY/VOICE 实时运行 · 情绪状态 · 语气控制 · 关系  │
├──────────────────────────────────────────────────────────┤
│                    能力层 (Skill Router)                    │
│  14 营养SKILL + 10 指南 → 可调用技能 · MCP网关 · 工具注册表  │
├──────────────────────────────────────────────────────────┤
│        底座层 (Agent Substrate) ← 本次补齐重点               │
│  记忆系统 · 多模型路由 · 多智能体 · 上下文引擎 · 定时任务    │
├──────────────────────────────────────────────────────────┤
│                    数据层 (Knowledge & Memory)              │
│  SQLite食物库 + 指南JSON · 患者档案 · FTS全文检索 · 向量(可选)│
└──────────────────────────────────────────────────────────┘
```

**与现状的差异**：现状只有「交互层 + 一层写死的对话逻辑 + 数据层」。v2 在中间插入「人格层 / 能力层 / 底座层」三块，把原本硬编码的东西全部"服务化"。

## 四、改造路线图（5 阶段）

### Phase 0 — 方案与审计
- [x] 代差对照、目标架构、复用清单（本文件）
- [x] 对标 LearnBuddy，锚定「营养行业智能体」范式
- [x] 确认范围（补底座 / 全套对齐 / 仅方案）后进入 Phase 1

### Phase 0.5 — 专家分身（LearnBuddy 核心范式，初稿已落地 ✅）
- [x] `data/expert-avatar.md`：专家分身定义（身份/方法论/决策框架/语言风格/边界声明），**运行时读取、修改即时生效**——即「本人审阅校准闭环」（改文件即本人修订）。
- [x] `src/main/expert-avatar.ts`：加载器（含内置兜底，文件缺失不炸）。
- [x] `persona.ts`：`buildSystemPrompt()` 注入分身章节（最高优先级）。
- [x] 设置页「专家分身」卡片（名称/来源/校准提示）。
- [ ] **本人校准**：由王润圆审阅 `data/expert-avatar.md`，修订后确认授权（v1 初稿日期 2026-08-10）。
- 验收：对话中营小养严格按分身定义出诊（先评估→再干预→后随访；指南优先；严守边界）。

### Phase 1 — 最小对等：记忆 + 多模型路由
- **记忆系统**：在 `~/.nutrition-buddy/memory/` 下建立长期记忆（用户偏好、常用设置）、会话记忆、患者档案（`patients/*.json`）。对话自动读写，支持"记住这个患者/这个偏好"。
- **多模型路由**：把 `llm.ts` 的单一 K3 调用改为可切换的模型路由（K3 / GLM / Kimi / MiniMax / Hy3），设置里可选主模型与推理模型。
- 验收：营小养能跨会话记住用户信息；可在设置里切换底层模型。

### Phase 2 — Skill 路由（替代硬编码工具）
- 把现有的 14 个营养 SKILL 与 10 部指南注册为**可调用技能**，对话按问题自动选技能（替代现在写死的 `query_guide` 等 7 个工具）。
- 工具注册表统一接管：食物查询、GI 分级、指南检索、工作台调用，都来自 skill 声明而非硬编码。
- 验收：问"痛风怎么吃"会自动路由到 gout 指南技能并产出结构化回答；新增一个指南无需改 `llm.ts`。

### Phase 3 — 画布 / Artifact + 多窗口
- 新增**画布面板**：食谱卡、营养评估报告、食物营养对比图直接在画布生成，可一键导出 PDF / 图片 / 可复制 Markdown。
- 多窗口：对话 ×N、知识库 ×N、患者 ×1、报告 ×N，窗口间可拖拽传递消息（参考 `MULTI_WINDOW_SESSION.md`）。
- 验收：对话中生成的食谱卡出现在画布，可导出；可开多个独立对话窗口。

### Phase 4 — MCP 连接器 + 多智能体
- **MCP 网关**：接入外部数据源 / 设备（如可穿戴、检验数据接口），营养Buddy 作为 MCP client。
- **多智能体**：把血脂 / 控糖 / 儿童肥胖 / MDT 拆成协作子代理，复杂病例由主代理派发、汇总。
- 验收：可通过 MCP 拉取外部数据；复杂咨询能自动分发给对应子代理并汇总。

### Phase 5 — 定时任务 + 多渠道（可选，对齐家族全集）
- **Cron**：患者随访提醒、饮食计划推送、定期科普生成。
- **多渠道**：微信等入口（可选，参考 QClaw `channels.wechat-access`）。
- 验收：可设定"每周一生成患者随访清单"；可选接入微信咨询入口。

## 六、风险与边界

- **不要重写领域资产**：14 SKILL、10 指南、SQLite 食物库是核心壁垒，只"服务化"接入，不重构数据。
- **专家分身必须本人校准**：分身定义 `data/expert-avatar.md` 是"以本人名义"出诊，未经本人审阅授权前，任何输出仍是 AI 行为而非本人执业行为；临床合规边界不因分身而放松。
- **离线优先不能丢**：家族其他产品依赖云端模型/通道，营养Buddy 必须保持核心知识本地化、断网可用。
- **临床合规边界**：所有输出保持"循证 + 可追溯 + 不替代诊断"，MCP/多渠道扩展时尤需注意患者隐私与授权。
- **范围控制**：Phase 1–3 即达成"核心对等"（记忆 + 多模型 + Skill 路由 + 画布）；Phase 4–5 是"全套对齐"，可按需求取舍。

## 七、验收标准（核心对等 = Phase 1–3，前置 = Phase 0.5）

0. 营小养按「专家分身」出诊：先评估再干预、指南优先、随访闭环、严守边界（专家分身生效）
1. 营小养能跨会话记住用户与患者信息（记忆系统生效）
2. 可在设置切换底层模型（多模型路由生效）
3. 新增一部指南无需改对话代码即可被自动调用（Skill 路由生效）
4. 对话产出的食谱卡 / 报告可在画布生成并导出（Artifact 生效）

达到这四条，营养Buddy 就不再是"不对等的小工具"，而是家族里**领域最深、临床最实的专家 Agent**。
